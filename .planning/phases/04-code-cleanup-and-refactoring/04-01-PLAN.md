    **D-14: Create shared SQLite DataSource bean (per D-14)**
    Create `feishu-bot-infrastructure/src/main/java/com/qdw/feishu/infrastructure/config/SQLiteConfig.java`:
    ```java
    @Configuration
    public class SQLiteConfig {
        @Bean
        public DataSource sqliteDataSource(FeishuProperties properties) {
            String dbPath = properties.getDbPath(); // or appropriate path source
            String connectionString = "jdbc:sqlite:" + dbPath;
            return DataSourceBuilder.create()
                .url(connectionString)
                .driverClassName("org.sqlite.JDBC")
                .build();
        }
    }
    ```
    If `FeishuProperties` doesn't have a dbPath, look at how both gateways currently construct their path — extract the same logic into the shared config. Use `@Primary` if needed.

    **Modify both gateways** to accept `DataSource` via constructor injection instead of calling their private `createDataSource()`:
    - `AppSessionGatewayImpl`: Remove private `createDataSource()` method. Change constructor to accept `DataSource dataSource` parameter. Use `new JdbcTemplate(dataSource)` instead of `new JdbcTemplate(createDataSource())`.
    - `ImContextBindingGatewayImpl`: Same approach — accept `DataSource` via constructor, remove `createDataSource()`.

    **D-15: Fix non-atomic upsert in ImContextBindingGatewayImpl.bind() (per D-15)**
    In the `bind()` method (around lines 284-347), replace the current SELECT → check → INSERT/UPDATE pattern with a single atomic SQL statement:
    ```sql
    INSERT INTO im_context_binding (context_key, app_id, session_id, created_at, updated_at)
    VALUES (?, ?, ?, ?, ?)
    ON CONFLICT(context_key) DO UPDATE SET
        app_id = excluded.app_id,
        session_id = excluded.session_id,
        updated_at = excluded.updated_at
    ```
    Remove the `findBinding()` call at the beginning of `bind()`. The method should be a single SQL execution. Keep the existing `created_at` on conflict (use `COALESCE(created_at, excluded.created_at)` or similar to preserve original creation time).

    **D-16: Fix optimistic lock in AppSessionGatewayImpl.updateSession() (per D-16)**
    In `updateSession()`, remove the preliminary `getVersion()` SELECT query. Instead, execute the UPDATE directly with `WHERE session_id = ? AND version = ?`. Check if `updated == 0` rows were affected to detect conflict. If `updated == 0`, throw `OptimisticLockException`. This reduces from 2 SQL round-trips to 1.

    **Update tests**: The existing test classes (ImContextBindingGatewayImplTest, AppSessionGatewayImplTest) construct gateways with their own test DataSources. Ensure tests still work by providing DataSource in test constructors. The test DataSources can remain independent (test isolation) — the shared bean is only for production wiring.
