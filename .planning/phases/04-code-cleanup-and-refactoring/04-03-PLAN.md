  <action>
    **D-12/D-13: Merge TopicState into ContextSessionState (per D-02, D-12, D-13)**

    Keep `ContextSessionState` in its current package (`domain/session/`) as the unified enum. It already has 4 values that cover the TopicState semantics:
    - `UNBOUND` ≈ `NON_TOPIC` (no binding to any app)
    - `BOUND_TO_OTHER_APP` — no TopicState equivalent, preserved per D-13
    - `IN_APP_NO_SESSION` ≈ `UNINITIALIZED` (bound to app but no active session)
    - `IN_APP_WITH_SESSION` ≈ `INITIALIZED` (fully ready)

    Add a `getDescription()` method to ContextSessionState matching TopicState's pattern, with Chinese descriptions for each value:
    ```java
    UNBOUND("未绑定"),
    BOUND_TO_OTHER_APP("已绑定其他应用"),
    IN_APP_NO_SESSION("未初始化"),
    IN_APP_WITH_SESSION("已初始化");
    ```

    **Update all TopicState consumers** (12 files reference TopicState):
    1. `OpenCodeSessionManager.detectTopicState()` — return type changes from `TopicState` to `ContextSessionState`. Mapping: `NON_TOPIC → UNBOUND`, `UNINITIALIZED → IN_APP_NO_SESSION`, `INITIALIZED → IN_APP_WITH_SESSION`.
    2. `OpenCodeApp.execute()` — update all `TopicState.XXX` comparisons to `ContextSessionState.XXX`.
    3. `OpenCodeCommandHandler.handle()` — update all TopicState references.
    4. `TopicCommandValidator` — update references.
    5. `CommandWhitelistValidator` — update references.
    6. Any test files that reference TopicState — update to ContextSessionState with correct values.

    **Delete TopicState.java** after all consumers are updated. Add a deprecation comment or just remove it — since this is a cleanup phase, clean removal is preferred.

    **D-03: Fix BotRoutingDecision (per D-03)**
    In `BotRoutingDecision.java`:
    - Remove the `FishuAppI app` field
    - Remove the import of `FishuAppI`
    - Update the `@AllArgsConstructor` to use only `(String appId, boolean persistBinding)`

    In `BotMessageAppService.java` (the consumer):
    - Replace `decision.getApp()` with `appRegistry.getApp(decision.getAppId())`
    - Add `AppRegistry` as a constructor parameter if not already injected
    - Update the null check: `if (decision == null || decision.getAppId() == null)` instead of checking `decision.getApp() == null`
    - Add null check after resolving: `FishuAppI app = appRegistry.getApp(decision.getAppId()); if (app == null) { ... }`

    In `BotMessageService.java` (where BotRoutingDecision is created):
    - Update the factory call to use `new BotRoutingDecision(appId, persistBinding)` — remove the `app` parameter

    **D-04: Fix FishuAppI @Deprecated (per D-04)**
    In `FishuAppI.java`:
    - The `execute(Message)` method is marked `@Deprecated` in favor of `execute(Message, MessageContext)`.
    - Decision: Remove the `@Deprecated` annotation and the Javadoc deprecation notice. The method is the PRIMARY API (not deprecated). The `execute(Message, MessageContext)` overload is the enhanced version that provides additional context — but `execute(Message)` remains the default. This is simpler than completing the migration to `execute(Message, MessageContext)` in all apps (which would be a larger change).
    - Keep both methods. Remove `@Deprecated` from `execute(Message)`. Update the Javadoc to say "Execute with basic message" instead of deprecation notice.
